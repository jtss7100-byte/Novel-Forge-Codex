# 영구 기억과 인물별 지식 관리

기억 검색 화면의 **영구 기억 관리**에서 기억 상태, 인물, 회차 범위, 출처 ID로 검토할 범위를 지정할 수 있습니다. 기준 회차와 장면 번호를 선택하면 선택한 인물이 해당 장면에서 쓸 수 있는 기억을 확인합니다. 회상이나 비선형 장면에는 연표의 확정 기준 사건을 지정합니다.

1. **기억 조회**로 검토할 원문, Revision, 분류 후보를 확인합니다. 목록은 20개 청크씩 표시하며 필터에 맞지 않는 페이지에서도 다음 페이지로 진행할 수 있습니다.
2. 개별 범위나 현재 페이지의 동일 후보를 선택합니다. 선택 항목은 승인 요청 한 건당 최대 16개입니다.
3. 공개 정보, 지정 인물만 아는 정보, 작가만 아는 정보, 사용을 보류할 정보를 구분합니다. 지정 인물의 획득 회차와 필요에 따라 확정 장면·연표 사건, 획득 경로를 선택합니다. 같은 획득 근거를 여러 범위나 인물에 적용할 수 있습니다. 획득 시점이 서로 다른 인물은 획득 근거를 각각 추가한 뒤 함께 저장합니다.
4. 대상 원문 범위와 변경 내용을 확인한 뒤 **선택한 기억 승인 저장**을 누릅니다. 완료와 실패는 항목별로 표시합니다. 응답을 확인하지 못하면 같은 요청으로 재시도하고, 버전이 바뀐 경우 최신 기록을 불러와 다시 검토합니다.
5. **승인 기록 조회**에서 이전 Revision의 기록과 각 승인 이력을 확인합니다. **문서 현황 집계**는 서버에서 원문별 상태를 페이지 단위로 계산합니다. 장편에서는 **이어서 집계**로 검토 범위를 늘립니다.

## Firestore 저장 구조

| 경로 | 저장 내용 |
| --- | --- |
| `users/{uid}/projects/{projectId}/memoryKnowledgeAnnotations/{annotationId}` | 원문 유형·ID·Revision·SHA-256·정확한 오프셋, 지식 범위, 인물별 획득 근거, 획득 시점 검증 해시, 시간 분류, 승인 버전·작가·시각 |
| `users/{uid}/projects/{projectId}/memoryKnowledgeDecisions/{operationId}` | 요청 해시, 이전 승인과 새 승인, 대상 승인 ID. CAS 및 멱등 재시도에 사용 |

신규 컬렉션에는 기존 Firebase ID Token과 서버의 프로젝트 소유권 검사로 접근합니다. Firestore Security Rules는 두 컬렉션의 Client SDK 직접 읽기와 쓰기를 차단합니다. 서버는 결과마다 별도 트랜잭션으로 활성 색인과 원본을 대조하고 두 컬렉션을 함께 저장합니다. 기존 컬렉션을 대상으로 한 백필, 복합 인덱스 추가, 운영 규칙 배포 또는 재색인은 이 기능의 선행 조건이 아닙니다.

## 기존 작품과 시간 기준

CANON 및 인물 참여는 원문 후보를 검토하는 근거가 됩니다. 공개 여부와 지식 획득은 작가가 확정합니다. 원문에 인용문이 있으면 해당 범위를 검토 대상으로 표시합니다. 인용부호만으로 발언자, 청자, 획득 여부를 확정하지 않습니다. 기존의 명시적 공개 정보, 작가 비밀, 장면별 승인 근거를 읽습니다. 전역 인물별 지식에는 확정된 획득 시점이 필요합니다. 과거 분류와 새 승인 사이에 충돌이 있으면 원문·범위를 검토할 때까지 집필에서 제외합니다.

동일 원문과 Revision이 같은 범위에서 유지되면 새 색인 청크 ID에도 승인을 적용할 수 있습니다. Revision이나 원문이 달라지거나 유효한 색인 세대가 사라지면 이전 승인은 이력에 남습니다. 범위 경계가 달라진 청크는 새 범위로 검토합니다. 삭제·색인 은퇴·초안·미확정 시점은 Writer에서 차단합니다.

같은 회차에서는 앞선 확정 장면만 근거로 사용합니다. 회상은 연표 순서를 사용합니다. 획득 경로가 추론 또는 불명이면 화면에서 이를 표시하고, Writer에 인물의 확인된 지식으로 전달하지 않습니다. 현황 집계의 집필 후보 수는 주어진 장면의 최종 회수를 보장하지 않습니다.
