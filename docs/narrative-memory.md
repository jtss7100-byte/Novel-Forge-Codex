# 서사 기억 연결

**기억 검색 → 서사 기억 연결**에서 출처를 기준으로 기존 정사의 연결과 작가가 저장한 연결을 확인합니다. 연표 사건 또는 복선의 **서사 연결** 버튼은 해당 출처를 미리 선택합니다. 목록의 **근거 검토**는 생성·수정 없이 출발과 도착을 채웁니다.

1. **연결 조회**에서 관계 유형, 작중 순서, 검증 상태를 확인합니다.
2. 출발과 도착 각각 **근거 조회**를 눌러 현재 정사의 정확한 원문 범위를 선택합니다.
3. 인과, 시간적 후속, 관련, 상태 변화 등 관계 유형을 선택합니다. 사건의 앞뒤만 확인되면 **사건 순서**를 사용합니다. **인물 상태 변화**는 상태가 바뀐 인물과 종류를 함께 지정합니다.
4. 양쪽 원문에 드러난 연결을 집필에서 사용하려면 공개 범위 체크박스를 선택합니다. 집필에서 사용할 연결은 양쪽 근거가 모두 해당 시점에 유효하고, POV 인물이 두 근거를 알 때만 적용됩니다.
5. 원문 범위와 관계를 확인한 다음 **검토 후보 저장**, **연결 승인**, **연결 거절**을 선택합니다. **변경 이력**에서 이전 버전을 확인합니다.
6. 집필 결과의 **장면별 서사 그래프** 진단에서 연결 종류, 확장 단계, 관계·인물 상태, 조회 비용과 제외 사유를 확인합니다.

## 파생 정보와 저장 정보

| 입력 | 처리 |
| --- | --- |
| 확정 연표의 장면, 인물, 세계관, 복선 ID와 회차·장면의 관련 사건 ID | 서버에서 파생합니다. 참여와 지식 획득은 별개 연결입니다. |
| 관계의 유효 사건, 같은 방향·인물 쌍의 다른 관계 | 유효 사건과 관계 이력을 탐색합니다. 조회가 잘렸거나 시점상 확인할 수 없는 상태가 있으면 현재 관계를 단정하지 않습니다. |
| 복선 설치·회수 장면과 사건 | 일치하는 확정 장면과 사건에 근거할 때 설치·회수를 구분합니다. 사건이 여러 개라 자동 식별할 수 없는 경우 관련 연결을 표시합니다. 강화 사건은 기존 관련 사건 및 강화 상태를 검증한 작가 승인으로 기록할 수 있습니다. |
| 인물 지식 획득 | 현재 POV 인물의 검증된 Stage 1.1 기록에 있는 사건을 사용합니다. 추론·불명·미승인 획득은 사용 대상에서 제외합니다. |
| 인과, 시간적 후속, 명시적 인물 상태 변화, 작가가 지정한 기타 연결 | 작가 후보 또는 승인으로 따로 저장합니다. 인물 상태는 기존 확정 사건을 근거로 하며, 기존 Curator의 미검증 상태나 새 정사 엔티티를 자동 생성하지 않습니다. |

`users/{uid}/projects/{projectId}/narrativeMemoryLinks/{linkId}`에는 양쪽 출처, 연결 유형, 공개 범위, 두 원문 Revision·SHA-256·오프셋, 두 정사 엔티티 지문, 승인 버전을 저장합니다. Link ID는 방향과 양쪽 ID, 유형, 해당하는 경우 인물과 상태 종류에서 결정됩니다. `narrativeMemoryDecisions/{operationId}`에는 요청 지문과 승인 전후 스냅샷을 보존합니다. 트랜잭션은 프로젝트 소유권·원문·활성 색인과 이전 버전을 확인합니다. Client SDK는 두 경로에서 직접 읽거나 쓸 수 없습니다.

정사 근거가 같은 범위에 유지되면 새로운 물리 청크 ID로도 연결을 확인합니다. Revision, 원문 범위, 정사 엔티티나 활성 세대가 달라지면 이전 승인은 이력으로 남고 검색에서 보류됩니다. 동일 노드의 관계 상태는 시간 순서와 정보 공개 여부를 함께 확인합니다.

## 집필 예산

- 최대 시작점 4개, 깊이 2단계, 방문 노드 12개, 노드당 연결 8개, 출처당 색인 청크 8개, 새 집필 후보 6개입니다. 시작점과 방문 상한을 낮춰 장편의 일반 하이브리드 검색과 원문 검증 여유를 확보했습니다.
- 그래프 탐색 조회는 장면당 6회·집필 실행당 8회입니다. 관련 원본, 부모 문서 및 승인 검증 조회는 장면당 24회·실행당 40회입니다. 묶음 조회와 단건 조회를 각각 Firestore 요청 한 건으로 셉니다.
- 그래프의 노드별 색인 조회는 기존 실행의 검색 요청 예산(기본 6회, 절대 상한 8회)을 함께 사용합니다. 최종 후보 수·원문 크기·추정 토큰 제한은 기존 예산 안에 유지합니다. 그래프 자체의 임베딩 및 생성 호출은 0건입니다.
- 관계 상태의 방향별 목록은 8건씩 최대 2페이지, 장면당 최대 6회·집필 실행당 최대 12회의 별도 읽기 한도를 사용합니다. 인물 상태 계열은 장면당 1개, 최대 8개 승인 상태를 확인합니다. 페이지가 잘리면 현재 상태를 확인 필요로 표시합니다.
- 그래프 오류나 입력 근거 변경 시 기존 검증된 하이브리드 후보를 사용합니다. 중간 노드도 권한, 활성 색인, 시점과 지식 검증을 통과해야 합니다. 승인된 연결 설명은 정확한 양끝의 근거가 최종 집필에 함께 뽑힌 경우에만 프롬프트에 들어갑니다.

기존 단일 필드 배열·동등 조건을 사용합니다. 운영 백필, 색인 변경, 규칙 배포는 이 개발에서 실행하지 않았습니다.

## 검증 범위

소규모 고정 정답 실험은 오프라인 후보와 동일한 질의·시간·POV·토큰 예산을 사용했습니다. 재회 사례의 Recall@4와 Precision@4는 25%에서 100%로 증가했습니다. 이미 관련 사건이 검색된 사례에서는 Recall@4가 100%로 유지됐고, 주변 기억이 순위에 끼어들어 nDCG@4는 1.0000에서 0.9060으로 하락했습니다. 세 가지 유출 지표는 양쪽 조건에서 0건입니다. 향후 테스트에서는 실제 장편을 대신하는 100·300·500화 합성 코퍼스에서 읽기 비용, 회수율과 순위 하락을 함께 확인합니다.
